## 三、AI 痕迹类（建议改）

### 修改 6：第 3.3.2 节 ComBat 安全封装段落（典型三段式 AI 罗列）

**【原文】**（第 3.3.2 节第二段及之后）

> ComBat 方法的统计模型与公式如第二章 2.3.1 节所述。尽管现有的 neuroCombat 库（Fortin 等，2018）提供了核心算法实现，但在与 Web 平台工作流对接时面临格式兼容与异常阻断的问题。为此，本系统专门封装实现了 run_combat_safe() 函数。**在数据维度对齐方面**，由于 neuroCombat 强制要求输入矩阵呈现"特征 × 样本"的格式，而本平台上下游数据流统一遵循机器学习标准的"样本 × 特征"结构，因此封装层在库函数调用前后加入了自动转置逻辑，消除了格式错位。
>
> **其次，针对异常输入导致的服务中断隐患**，封装函数引入了完备的降级机制。当检测到输入数据存在任一批次样本数不足 2 个、有效批次数少于 2 个，或检测到全特征恒定等极端退化条件时，系统会主动记录警告日志，并自动切换至前述的 Baseline 对齐方法或直接返回原始矩阵。这避免了底层数学库抛出未捕获异常进而导致整个 Web 接口崩溃的风险。**最后，在参数扩展方面**，该函数通过可选的 `biological_covariates` 参数，支持显式传入用户的生物学分组标签。这使得算法在执行经验 Bayes 收缩时能同步估计协变量效应，进而确保真实的生物学组间差异在校正过程中得到妥善保护而未被抹除。

**【修改后】**

> ComBat 方法的统计模型与公式如第二章 2.3.1 节所述。现有的 neuroCombat 库（Fortin 等，2018）提供了核心算法实现，但要直接挂到 Web 工作流上仍有两处问题需要处理：一是 neuroCombat 要求输入矩阵采用"特征×样本"布局，而本平台上下游统一采用"样本×特征"，因此封装层 `run_combat_safe()` 在调用库函数前后自动完成转置；二是 neuroCombat 在批次样本数不足 2、有效批次数少于 2、或出现全特征恒定等退化场景下会直接抛出未捕获异常，足以击穿整个 Web 接口，因此封装层加入了前置校验，遇到上述情况主动记录警告并退回 Baseline 对齐或返回原矩阵。
>
> 此外，`run_combat_safe()` 预留了 `biological_covariates` 可选参数，用户传入分组标签后，经验 Bayes 收缩会同步估计协变量效应，保护组间差异不被一同抹去。run_combat_safe() 的整体异常降级逻辑如图 3-2 所示。

> 修改理由：原文用"在……方面/其次……/最后……"显式三段式编号，是典型 AI 列点腔；改写后用自然行文承接，并把"两处需要处理的问题"合并为一段以增强逻辑张力。
